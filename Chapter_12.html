Introduction to SQL & RDBMS

Understand what a database is, how RDBMS works, and what SQL is used for.

A Database is an organised collection of inter-related data stored so that it can be easily accessed, managed, and updated. An RDBMS stores data in the form of tables with rows and columns.

TermMeaningExample
Table / RelationCollection of rows and columnsStudent
Row / TupleOne record in the tableOne student's data
Column / AttributeA field / propertyName, Age
Primary KeyUniquely identifies each rowAdmno
Foreign KeyLinks two tablesDept_id in Employee
💡 Tip

Popular RDBMS: MySQL, Oracle, MS SQL Server, PostgreSQL, SQLite.

SQL Overview

SQL (Structured Query Language) is the standard language for interacting with relational databases.

SQL is not case-sensitive for keywords (SELECT = select), but conventionally written in uppercase. Statements end with a semicolon (;).

12.2 Constraints

Constraints enforce rules on the data in a table to maintain accuracy and integrity.

ConstraintBadgeDescription
PRIMARY KEYPKUniquely identifies each row; NOT NULL + UNIQUE combined
FOREIGN KEYFKLinks to PRIMARY KEY in another table; enforces referential integrity
NOT NULLNNColumn must have a value — NULL not allowed
UNIQUEUQAll values in column must be different; allows one NULL
CHECKCKLimits values to satisfy a condition (e.g. Age > 0)
DEFAULTDFAssigns a default value when none is provided
Constraints in CREATE TABLETextbook
CREATE TABLE Student (
  Admno   INT          PRIMARY KEY,
  Name    VARCHAR(30)  NOT NULL,
  Gender  CHAR(1)       CHECK (Gender IN ('M','F')),
  Age     INT          DEFAULT 17,
  Place   VARCHAR(25)
);

12.5 DROP & TRUNCATE

Permanently remove a table or clear all its rows.

CommandEffectCan Rollback?
DROP TABLERemoves table structure AND all data permanentlyNo
TRUNCATE TABLEDeletes all rows; keeps the table structure intactNo (DDL)
DELETE (no WHERE)Deletes all rows; keeps structureYes (DML)
⚠ Warning

DROP and TRUNCATE are irreversible. Always take a backup before using them in production.

DROP TABLE syntaxTextbook
DROP TABLE Student;          -- removes table completely
TRUNCATE TABLE Student;     -- clears data, keeps structure

12.7 UPDATE

Modify existing records in a table. Always use WHERE to target specific rows.

Syntax

UPDATE table_name
SET col1 = val1, col2 = val2
WHERE condition;
⚠ Always use WHERE

Without a WHERE clause, UPDATE modifies every row in the table.

Update a student's placeTextbook
UPDATE Student
SET Place = 'Coimbatore'
WHERE Admno = 101;
Try it — update then verify

12.8 DELETE

12.9 SELECT Statement

The most important SQL statement — retrieve data from one or more tables.

Syntax

SELECT [DISTINCT] col1, col2 | *
FROM table_name
[WHERE condition]
[GROUP BY col]
[HAVING condition]
[ORDER BY col [ASC|DESC]];
Basic SELECT examplesTextbook
SELECT * FROM Student;                      -- all rows, all columns
SELECT Name, Age FROM Student;              -- specific columns
SELECT DISTINCT Place FROM Student;         -- unique places only
SELECT Name, Age * 2 AS DoubleAge FROM Student; -- computed column

12.12 GROUP BY & HAVING

Group rows by a column value, then apply aggregate functions to each group.

📌 Remember

WHERE filters rows before grouping. HAVING filters groups after aggregation. You cannot use aggregate functions in WHERE.

GROUP BY examplesTextbook
-- Count students by gender
SELECT Gender, COUNT(*) AS Count
FROM Student
GROUP BY Gender;

-- Average age per place, only where avg > 16
SELECT Place, AVG(Age) AS AvgAge
FROM Student
GROUP BY Place
HAVING AVG(Age) > 16;
Try it

12.13 ORDER BY

Sort query results in ascending (ASC) or descending (DESC) order.

ORDER BY examplesTextbook
SELECT * FROM Student ORDER BY Name;           -- alphabetical ASC (default)
SELECT * FROM Student ORDER BY Age DESC;       -- oldest first
SELECT * FROM Student ORDER BY Place, Name;     -- multi-column sort
Try it

12.14 Transaction Control (TCL)

Manage transactions to ensure data consistency — commit or undo changes.

CommandEffect
COMMITPermanently saves all changes made in the current transaction
ROLLBACKUndoes all changes since the last COMMIT
SAVEPOINT nameSets a named checkpoint within a transaction
ROLLBACK TO nameReverts to a specific savepoint
SAVEPOINT & ROLLBACK exampleTextbook
START TRANSACTION;
INSERT INTO Student VALUES (110, 'Test', 'M', 17, 'Chennai');
SAVEPOINT sp1;
DELETE FROM Student WHERE Admno = 110;
ROLLBACK TO sp1;    -- row 110 is back
COMMIT;             -- save everything up to sp1
📌 Note

DDL statements (CREATE, DROP, ALTER, TRUNCATE) cause an implicit COMMIT and cannot be rolled back.
